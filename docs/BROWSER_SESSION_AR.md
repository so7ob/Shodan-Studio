# المتصفح التفاعلي لمهام HTML — الإصدار 1.4

عند ظهور `HTTP_403 / BROWSER_CHALLENGE` يمكنك فتح صفحة Shodan التي تعمل على
خادم Debian من داخل لوحة Studio على جهازك الآخر. تستخدم الصفحة والعامل اللاحق
ملف المتصفح نفسه وخروج VPN نفسه. نجاح VPN لا يثبت السماح بالبحث في الموقع.

## الاستخدام

1. افتح المهمة المتوقفة أو التي تنتظر إدخالًا، واختر HTML وملف VPN في بطاقة
   **اتصال المهمة — Job Network**. المتصفح التفاعلي يتطلب اتصالًا معزولًا؛
   وضع Direct لا يدعمه.
2. اضغط **فتح المتصفح التفاعلي**. يبدأ Chromium على الخادم، وتظهر صورة صفحته
   داخل اللوحة. انقر في الصورة لإكمال التحقق يدويًا أو تحديد حقل تسجيل الدخول.
3. أدخل النص في الحقل أسفل الصورة واضغط **إرسال النص**؛ يُمسح الحقل فور إرساله.
   استخدم **الحقل التالي Tab** و**Enter** للانتقال والإرسال، أو لوحة المفاتيح
   بعد تحديد الصورة. لا يوجد رفع ملفات أو تنزيلها من المتصفح البعيد.
4. إذا نقلك تسجيل الدخول إلى الصفحة الرئيسية أو صفحة الحساب، اضغط **العودة إلى
   نتائج المهمة**. يعيد الزر فتح صفحة المهمة داخل المتصفح نفسه، مع الاحتفاظ
   بتسجيل الدخول وخروج VPN. لا ينقلك التطبيق تلقائيًا أثناء إدخال بياناتك.
   عندما تظهر النتائج اضغط **فحص الصفحة**. لا يتاح **استكمال المهمة** إلا بعد
   HTTP 200 وتحليل صفحة facet صحيحة للاستعلام المطلوب. يعاد الفحص عند الاستكمال.
5. استكمل المهمة. يحتفظ العامل بالنتائج السابقة وCheckpoint ويجلب الصفحات من
   هذه الجلسة. إذا عاد رفض الوصول يتوقف بأمان لإدخال يدوي آخر.
6. اضغط **إنهاء الجلسة** لإتاحة النفق لبقية الطابور أو لتغيير الدولة. إخفاء
   النافذة وحده لا ينهي الجلسة؛ تنتهي بعد 30 دقيقة من عدم التفاعل عند توقف العامل.

إذا أُغلقت جلسة كانت تعمل، يمكن فتحها مجددًا وفحص الصفحة. لا يتحول العامل بصمت إلى curl.
زر **فحص الصفحة** يقرأ الصفحة الحالية ولا يعيد تحميلها. إذا كرر الموقع نفسه
التحقق، فإن تكرار الفحص أو إغلاق الجلسة وإعادة فتحها لا يضمن قبولها. تبقى
المهمة متوقفة ونتائجها وCheckpoint محفوظين؛ إنهاء الجلسة يحرر النفق فقط.
زر **العودة إلى نتائج المهمة** يتاح عندما تكون في صفحة أخرى، ولا يقبل رابطًا
من المستخدم. يعود إلى الفرع المطلوب حاليًا إن كان العامل قد بدأ التقسيم؛
نجاح تسجيل الدخول وحده لا يعني نجاح قراءة نتائج ذلك الفرع.
عند HTTP 429 تعرض النافذة تقييد الطلبات، ويحفظ العامل مدة `Retry-After` إن
حددها الموقع، ويرفض استكمال الطلب قبلها. في وضع Failover المفعّل تُغلق
الجلسة بعد حفظ التقدم، ويُجرّب الاتصال التالي، ثم تُفتح الجلسة تلقائيًا بملف
ذلك الاتصال. يرسل العامل الطلب بعد مهلة المصدر؛ ولا يؤدي انتظار محفوظ
وحده إلى تبديل متكرر. ينطبق التبديل أيضًا على استمرار فشل الاتصال بـ Shodan.
الحد الافتراضي للمهام الجديدة 20 تبديلًا، ويمكن ضبطه حتى 100؛ لا تتغير
الحدود المحفوظة للمهام السابقة. قد يتطلب الاتصال الجديد تسجيل دخول أو تحققًا.
أثناء الاستخراج تُمنع عمليات إدخال المتصفح وتبديل النفق؛ أوقف المهمة مؤقتًا
وانتظر حفظها أولًا. تُحجز قائمة الانتظار للمهمة صاحبة الجلسة حتى إنهائها،
ويظهر فشل أو طلب إدخال بوضوح بدل نجاح شكلي.

## حدود الوصول الفعلية

لا يحل التطبيق CAPTCHA آليًا، ولا يخفي استخدام أدوات التحكم بالمتصفح، ولا
ينقل cookies من جهازك. قد يرفض Shodan أو Cloudflare الجلسة حتى بعد تفاعلك؛
تذكر [وثائق Cloudflare](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)
أن المتصفحات الآلية غير مدعومة للتحقق. لا يمكن ضمان نجاح استخراج HTML.
الوصول إلى البحث قد يتطلب تسجيل دخول وصلاحيات يمنحها الموقع لحسابك؛ اشتراك
Amnezia Premium لا يمنح صلاحيات Shodan.

إذا بقيت صفحة منع الوصول، لا تكرر تبديل الدول بوصفه تعافيًا شبكيًا. أوقف
الجلسة واحتفظ بالمهمة ونتائجها إلى أن يتوفر وصول يسمح به الموقع. تقرير الاختبار
يفصل نجاح النقل والواجهة عن نجاح بحث حي.

### توضيح الإصدار 1.5.1

توضح النافذة الآن أن بقاء التحقق يعني توقف المهمة وحفظ نتائجها، وأن الفحص
أو تكرار إنشاء الجلسة لا يضمن قبول الموقع. هذا تعديل للإرشادات، وليس إصلاحًا
مزعومًا لتحقق Cloudflare. اجتازت اختبارات المتصفح القائمة 27 اختبارًا محليًا.
أُعيد تشغيل خدمة الويب وحدها؛ بقيت الجلسة وVPN والبيانات كما هي، مع نسخة
احتياطية اختُبرت استعادتها. [سجل النشر والتراجع](browser-guidance-deployment.json).
للتراجع عن هذا التعديل فقط، أعد رابط `current` إلى `previous_release` المسجل
بعد إيقاف خدمة الويب، ثم شغّلها؛ لا تستبدل قاعدة البيانات أو نقاط الاستكمال.

## التثبيت والترقية على المسارات المتحققة

هذا مكوّن اختياري فوق VPN Manager الحالي، وليس بديلًا عن إعداداته. يلزم
Chromium مع sandbox ودعم user namespaces وXvfb، ونحو 500 MiB لمساحة الحزم
إضافة إلى ملفات المتصفح. يرفض بدء جلسة جديدة إذا بقي أقل من 200 MiB.

```bash
sudo apt update
sudo apt install --no-install-recommends chromium xvfb xauth
bash install-debian.sh --check
bash tools/install_vpn_helper.sh --check
bash tools/install_browser.sh --check
```

أوقف أو أتمم المهام أولًا. احفظ وجهة الإصدار الحالي خارج الحزمة قبل التحديث،
ثم أوقف خدمتي التطبيق فقط. النسخة الخاصة يجب أن تشمل:

- `/var/lib/shodan-studio` كاملًا، مع SQLite وCheckpoints والنتائج.
- `/etc/default/shodan-studio` و`/etc/shodan-studio/vpn`.
- وحدتي `shodan-studio.service` و`shodan-studio-vpn.service` من `/etc/systemd/system`.
- `/var/lib/shodan-studio-browser` إن كان موجودًا؛ يحتوي جلسات خاصة ويحتاج حماية
  النسخ الاحتياطية نفسها. لا تضعه في Git أو حزمة إصدار عامة.

```bash
readlink -f /opt/shodan-studio/current
sudo systemctl stop shodan-studio shodan-studio-vpn
sudo install -d -m 0700 /var/backups/shodan-studio
# للمرة الأولى، لا يوجد مجلد متصفح لإدراجه في الأرشيف:
sudo bash -c 'umask 077; tar -C / -czf /var/backups/shodan-studio/pre-browser-$(date +%Y%m%d-%H%M%S).tar.gz var/lib/shodan-studio etc/default/shodan-studio etc/shodan-studio/vpn etc/systemd/system/shodan-studio.service etc/systemd/system/shodan-studio-vpn.service'
sudo bash install-debian.sh --no-start
sudo bash tools/install_browser.sh
sudo bash tools/install_vpn_helper.sh --no-start
sudo systemctl start shodan-studio-vpn shodan-studio
curl --fail http://127.0.0.1:8787/health
```

الترقية من 1.3.1 إلى 1.4.0 لا تغير مخطط SQLite (`user_version=1`). تحقق من
سلامة القاعدة وأعداد المهام والنتائج ومن بقاء ملفات الاستكمال بعد التحديث.
لا تُعد تشغيل SSH أو AmneziaVPN. عند إعادة تشغيل broker يبدأ دون نفق متحقق؛
يُنشأ اتصال العامل عند طلب فتح الجلسة، دون تعديل المسار الافتراضي للمضيف.

## التراجع والاستعادة

أغلق الجلسة وأوقف المهام، ثم أوقف خدمتي التطبيق. استعد رابط `current` إلى
**وجهة الإصدار المحفوظة قبل الترقية**، واستعد وحدتي systemd من النسخة الخاصة
أو من مجلد `deploy` للإصدار القديم، ثم نفّذ `systemctl daemon-reload` وشغّل
الخدمتين. أبقِ مهام المتصفح متوقفة؛ الإصدار 1.3.1 لا يفهم نقل HTML بالمتصفح.
لا تحذف بياناتها أو تعِد استكمالها به لاعتبارها جلسات متصفح.

لا يلزم استبدال SQLite عند التراجع عن الكود. عند الحاجة إلى استعادة كاملة،
احفظ الحالة الحالية أولًا، وافحص الأرشيف في مجلد منفصل وتحقق من
`PRAGMA integrity_check` وأعداد الصفوف. استعد مجلد البيانات كاملًا أثناء توقف
الخدمات، لا قاعدة قديمة فوق WAL/SHM أحدث. الاستعادة الكاملة تلغي التغييرات
اللاحقة للنسخة الاحتياطية.

## الأمان والتشخيص

خادم الويب يبقى `shodan-studio`؛ المتصفح يعمل بحساب `shodan-browser` دون
capabilities، داخل `ssvpn-worker` مع sandbox فعال. API الإدارة محمي بالمصادقة
وCSRF. التحكم يقتصر على صورة ونقر ونص ومفاتيح محددة؛ لا يوجد منفذ VNC/CDP
عام أو تنفيذ JavaScript/أوامر يختارها العميل.

ملفات الجلسة في `/var/lib/shodan-studio-browser/<profile-id>` بصلاحية 0700؛
حساب الويب لا يقرأها. لا تُكتب النصوص المدخلة أو الصور أو cookies في سجل
التدقيق. وصول إدارة Studio يجب أن يكون عبر HTTPS أو SSH tunnel عند إدخال
بيانات حساب على شبكة غير موثوقة، كما في دليل التشغيل الأساسي.

تُمنع وجهات الشبكات الخاصة وloopback وlink-local لعملية المتصفح، وتقتصر
طلبات الصفحة على نطاقات Shodan ومضيف تحقق Cloudflare المعتمدين. DNS الخاص
داخل LAN غير مدعوم لهذا المتصفح؛ استخدم DNS عامًا صالحًا داخل النفق. إذا تغيرت
نطاقات الموقع، تحتاج قائمة السماح إلى مراجعة، ولا يوجد تجاوز عام من الواجهة.

إعادة تشغيل خدمة الويب وحدها تعيد حجز الجلسة الحية من broker. إعادة تشغيل
broker أو الجهاز تغلقها وتلغي تحققها؛ فتح جديد وفحص فعلي مطلوبان، حتى إن بقيت
ملفات الجلسة. فقد النفق يبقي المتصفح دون اتصال مباشر، ويغلقه فحص العزل عند
التفاعل التالي. يبقى Checkpoint والنتائج محفوظين.

للاختبار المحلي دون Shodan، بصلاحيات root بعد تجهيز حساب المتصفح:

```bash
python3 tools/verify_browser_session.py --run-root-lab
```

ينشئ خدمة مؤقتة وشبكة منفصلة بلا إنترنت، ويفحص Chromium الحقيقي وnamespace
sandbox وSeccomp ووسائل الإدخال ومنع الخروج، ثم يزيل موارده الاختبارية.
