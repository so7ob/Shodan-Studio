# سجل الاستعلامات ونتائجها — Issue #31

تظهر بطاقة «الطلب الجاري / آخر طلب» في نظرة المهمة العامة. تعرض الاستعلام كاملًا،
والمرشح والمصدر وحالة النتيجة والإجمالي وعدد عناصر الصفحة والمدة. أثناء فاصل
الطلبات تبقى نتيجة آخر طلب ظاهرة؛ الانتظار لا يعني أن الطلب التالي أُرسل.

يفتح «سجل التنفيذ» على «الطلبات ونتائجها». وسّع المحاولة لعرض قيم المرشح وأعداد
سجلاتها، أو انسخ الاستعلام. تُحمّل المحاولات الأقدم والقيم الإضافية عند الطلب.
يمكن اختيار «كل الأحداث» لعرض رسائل المحرك والتحذيرات والتقدم أيضًا. يحافظ
التحديث التلقائي على الصف المفتوح والتركيز والقيم التي حمّلها المستخدم.

## معنى النتائج

- «نجح» يعني نجاح قراءة النتيجة؛ لا يضمن اكتمال تغطية Shodan.
- «لا توجد نتائج» يخص استجابة فارغة مؤكدة. «المرشح بلا معلومات» لا يعني أن
  الاستعلام الأساسي بلا نتائج، ولا يتطلب حل اختبار أمان.
- تُعرض حالات 429 وCloudflare وتسجيل الدخول وفشل الاتصال بصورة منفصلة.
- عدد عناصر الصفحة قد يمثل قيم مدن/منافذ، أو سجلات صفحة API؛ لا يساوي إجمالي IP.
  «عناوين IP جديدة» لطلبات IP يحسب إضافات SQLite الفعلية في المعاملة نفسها مع
  حفظ العناوين، فلا تزيده إعادة إرسال دفعة أو استكمال checkpoint أقدم من البيانات.
- المدة تخص تنفيذ الطلب ومعالجته، دون الفاصل السابق أو انتظار إعادة المحاولة.
  رمز HTTP يظهر عند توفره؛ لا يُختلق 200 من مجرد نجاح التحليل.
- قراءة الذاكرة المؤقتة لها سجل مستقل موسوم، ولا تزيد ميزانية طلبات Shodan.
- المعلومات غير المحفوظة تظهر «غير متاحة». المحاولة التي انقطع تسجيل نتيجتها
  تظهر «النتيجة غير مؤكدة»، ويُستفاد من التقرير النهائي عند تطابق معرّف المحاولة.

## API والتخزين

المسارات تتطلب جلسة المستخدم نفسها، ويُتحقق من ارتباط المحاولة بالمهمة:

- `GET /api/jobs/{id}/requests?before=0&limit=50`: يعيد `items` بالأحدث أولًا
  و`next_cursor` للمحاولات الأقدم؛ أقصى حجم صفحة 200.
- `GET /api/jobs/{id}/requests/{request_id}?offset=0&limit=100`: يعيد `request`
  و`items` لقيم المرشح و`total` و`offset` و`has_more`؛ أقصى حجم صفحة 1000.
- `latest_request` حقل إضافي في بيانات المهمة، أو `null` عند عدم وجود محاولة.

الملخص يتضمن `request_id` و`origin` و`status` و`query` و`facet` و`source`،
وحقول `number` و`session_number` و`retry_number` و`api_page`، والأعداد
`total_records` و`row_count` و`new_unique_ips`، و`started_at` و`finished_at`
و`duration_ms` و`http_status` و`error`. الحقول المجهولة `null`. قائمة الطلبات
تضيف `seq` للمؤشر و`details_count` لعدد القيم المحفوظة حاليًا.

تبقى المحاولات والقيم في جداول مستقلة عن سجل الأحداث المحدود. التحديثات تحمل
معرّف المحاولة نفسه، وإعادة المحاولة تحصل على معرّف جديد. قيم المرشحات تُرسل
في دفعات صغيرة، بحد 100 قيمة ونحو 64 KiB للدفعة. تُختصر نصوص القيم الاستثنائية
إلى 4096 حرفًا مع `truncated: true` ووسم ظاهر؛ لا يتغير الاستعلام أو بيانات
المحرك الأصلية. لا تُحفظ الاستجابات الخام أو الرؤوس أو بيانات الاعتماد.

## التاريخ القديم والاستكمال

بعد امتلاك قفل المدير وقبل تشغيل الطابور، يُستعاد المتاح محليًا من التقارير
ورسائل بدء الطلبات وcheckpoint. تتم المطابقة باستخدام الجولة والمحاولة والمصدر
والمرشح والاستعلام وصفحة API وحدود زمن التقرير، ولا يكفي تشابه الاستعلام.
الاستيراد متكرر بأمان؛ بصمات المصادر تمنع إعادة المعالجة عندما لا تتغير.
نص الاستعلام في رسالة قديمة قد يكون مختصرًا وفق تنسيق السجل القديم.

قيم checkpoint تظهر «لقطة محفوظة؛ ليست محاولة جديدة»، ولا تثبت نجاح محاولة
فاشلة، ولا تُستخدم لاختلاق مدة أو عدد عناوين جديدة. التقرير الحديث يمكن أن يكمل
نتيجة ضاعت بين العامل والمدير باستخدام معرّفها؛ نسبة الإضافات إلى محاولة بعينها
تبقى مجهولة إن لم تكن مسجلة في معاملة SQLite. لا تُرسل أي طلبات Shodan عند
الاستيراد أو عرض السجل. حذف المهمة يحذف تاريخها وقيمها المرتبطة.

لم تتغير استراتيجية التخطيط أو حدود الطلبات أو الفاصل أو سياسات VPN والتحقق.
تُحفظ النسخة الاحتياطية قبل النشر وتُراجع سلامة المهام والعناوين والإعدادات بعده.
