# حسابات Shodan المحفوظة

افتح **حسابات Shodan** من القائمة الجانبية أو من بطاقة اتصال المهمة. يمكنك
إضافة عدة حسابات وتعديل بياناتها وحذفها. أدخل بياناتك من واجهة التطبيق؛ لا
تحتاج إلى إرسالها في المحادثة أو وضعها في ملفات الاستعلام.

لتسجيل الدخول:

1. أوقف مهمة HTML مؤقتًا وأغلق جلسة المتصفح المفتوحة إن وجدت.
2. اختر الحساب من **حساب Shodan للمهمة**، مع اتصال VPN معزول مضبوط للمهمة.
3. افتح المتصفح التفاعلي واضغط **تسجيل الدخول بالحساب**. ينتقل المتصفح إلى
   صفحة `https://account.shodan.io/login` ويملأ النموذج ويرسله مرة واحدة.
4. أكمل CAPTCHA أو رمز التحقق إذا طلبهما الموقع. رسالة «أُرسلت بيانات الدخول»
   تصف الإرسال فقط؛ راجع الصفحة للتأكد من قبول الحساب.
5. اضغط **العودة إلى نتائج المهمة** ثم **فحص الصفحة**. يصبح الاستكمال متاحًا
   بعد التحقق من صفحة النتائج. لا تُرسل محاولة استكمال تلقائية بمجرد تسجيل الدخول.

يستخدم الجمع ملفات الارتباط من المتصفح نفسه. لكل حساب جلسة منفصلة عن الحسابات
الأخرى وعن الجلسة اليدوية القديمة. تبقى هوية الحساب عند تبديل VPN؛ لا يجري
التبديل بين حسابات Shodan تلقائيًا. تظل ميزانية الطلبات وفاصلها وRetry-After
وصلاحيات الحساب وحدوده قائمة. حساب المتصفح مستقل عن مفتاح API. عند اختيار حساب، يمنع الاستكمال عبر HTTP
المجهول حتى فتح متصفح المهمة والتحقق من صفحة نتائجه.

الحسابات الاجتماعية Google وغيرها تحتاج إلى الدخول اليدوي؛ النموذج المحفوظ
يدعم اسم المستخدم وكلمة المرور في [صفحة Shodan الرسمية](https://account.shodan.io/login).
توضح [أسئلة إدارة الحساب](https://help.shodan.io/the-basics/account-faq) أن حسابات
الدخول الاجتماعي قد تكون منفصلة عن حساب Shodan التقليدي حتى مع البريد نفسه.

## الحفظ والنسخ الاحتياطي

تحتاج هذه الخاصية الاختيارية إلى حزمة Debian `python3-cryptography` في Python
الذي يشغّل خدمة الويب، كما في تكامل Premium:

```bash
sudo apt install python3-cryptography
```

تُحفظ بيانات الدخول مشفّرة باستخدام Fernet في جدول `shodan_accounts` بقاعدة
البيانات. المفتاح في ملف `shodan-accounts.key` داخل مجلد بيانات التطبيق بملكية
مستخدم الخدمة وصلاحيات 0600. تُعرض أسماء المستخدمين للمستخدم المصادق عليه،
لكن كلمات المرور لا تُعاد عبر API ولا تُضاف إلى المهام أو السجلات أو التقارير
أو نقاط الاستكمال أو وسائط العمليات. المفتاح والبيانات معًا يتيحان فك التشفير؛
حماية ملفات الخادم والنسخ الاحتياطية تظل ضرورية.

انسخ قاعدة البيانات وملف المفتاح معًا. فقد المفتاح لا يؤدي إلى توليد مفتاح
بديل فوق بيانات قائمة؛ يلزم استعادة المفتاح الأصلي. استيراد Checkpoint لا
ينقل بيانات الحساب، ويجب اختيار الحساب محليًا في الوجهة الجديدة.

في التعديل، اترك كلمة المرور فارغة للاحتفاظ بها. تغيير اسم المستخدم أو كلمة
المرور ينشئ جلسة جديدة ويزيل ملفات جلسة الحساب القديمة. حذف الحساب يزيل بياناته
وجلساته المحفوظة ويرفع ربطه بالمهام. يلزم إغلاق المتصفح وإيقاف التنفيذ قبل
تعديل حساب قائم أو حذفه؛ إضافة حساب آخر متاحة أثناء وجود جلسة مفتوحة.

للتحديث التشغيلي، يتغيّر وسيط المتصفح أيضًا: احفظ تقدم العمل وأغلق جلسة المتصفح،
ثم حدّث التطبيق وأعد تشغيل `shodan-studio-vpn` و`shodan-studio`. قد يحتاج اتصال
VPN إلى إعادة التهيئة بعد إعادة تشغيل الوسيط. تثبيت كود الويب وحده لا يحدّث
الوسيط الجاري. دليل قبول هذه الخاصية لا يدّعي نشرها على الخدمة.

## التحقق

اختبارات الحسابات تستخدم بيانات اصطناعية. فُحص الحفظ المشفّر واستعادة النسخة
الاحتياطية ومنع كشف الأسرار، وصلاحيات API وCSRF، واختيار الحساب، وفصل ملفات
الارتباط، والاستكمال بعد تبديل VPN، وChromium وPatchright. اختبار المتصفح يعترض
الصفحات محليًا ويتحقق من الأصل الرسمي ومن POST وحفظ حقول CSRF وعدم اتباع
`formaction` مخالف، دون طلب حي إلى Shodan أو استخدام بيانات حساب حقيقي.

```bash
PYTHONPATH=tests python3 -m unittest test_shodan_accounts test_vpn_failover
python3 tests/serve_vpn_fixture.py --accounts --port 8799
# من طرفية أخرى، مع Playwright و @axe-core/playwright:
NODE_PATH=/path/to/node_modules STUDIO_TEST_CHROMIUM=/usr/bin/chromium node tests/browser_shodan_accounts.cjs http://127.0.0.1:8799
NODE_PATH=/path/to/node_modules STUDIO_TEST_CHROMIUM=/usr/bin/chromium node tests/browser_shodan_login.cjs
```

[دليل فحص الواجهة](shodan-accounts-evidence/ui.json): 375 و1280 بكسل، إدخال بلوحة
المفاتيح، وصفر مخالفات axe في الأجزاء المختبرة. لم يُجرَ اختبار بقارئ شاشة فعلي
أو تسجيل دخول حي؛ قد يستلزم تغيّر نموذج Shodan مستقبلًا تعديل محددات النموذج.
