# مستودع الأهداف ومهام الإثراء — Issue #33

يجمع المستودع عناوين IPv4 وIPv6 من جميع مهام الاستخراج، بما فيها المتوقفة
والملغاة. لكل IP سجل موحد، مع فصل مجموعة البيانات التجريبية. تبقى الأدلة
ونسخة اسم المهمة واستعلامها بعد حذف المهمة الأصلية.

## الفلاتر والإحصاءات

افتح **مستودع الأهداف** من القائمة. الفلاتر تشمل IP/CIDR وأسماء المضيف،
والدولة والمدينة، والبورت والبروتوكول والمنتج، والمؤسسة وASN، والمهمة
والاستعلام ومصدر الاكتشاف ومصدر التفاصيل وحالة الإثراء والفترة الزمنية.
أزرار التوزيع حسب الدولة والمدينة والبورت والحالة تطبق الفلتر مباشرة.

تستخدم القائمة والإحصاءات والتصدير مجموعة الأهداف المطابقة نفسها. أعداد
الخدمات ورسوم البورتات تشمل خدمات تلك الأهداف؛ قد يكون للمضيف عدة خدمات.
فلاتر البورت والبروتوكول والمنتج تطابق خدمة واحدة، وفلاتر المهمة والاستعلام
ومصدر الاكتشاف والتاريخ تطابق واقعة اكتشاف واحدة. أعداد المهام ومنحنى الأيام
يلتزمان بفلاتر وقائع الاكتشاف أيضًا.

التصفح بصفحات من 50 هدفًا. تصدير TXT/CSV/JSON يشمل النتائج المطابقة، ويقرأ
لقطة SQLite واحدة مع استمرار العامل عبر WAL. حد التصدير 128 MiB؛ ضيّق
الفلاتر إذا تجاوزه الملف. خلايا CSV النصية محمية من تفسير النصوص كصيغ.

اضغط العنوان لعرض خدماته ومصدر كل معلومة ولقطاتها التاريخية، والمهام
والاستعلامات ومرات العثور عليه، ومهام الإثراء المرتبطة به. تعرض بيانات
المصدر كنص؛ لا يُنفذ HTML أو JavaScript من النتائج.

## الأوقات ودلالة البيانات

- أقدم وآخر اكتشاف موثقين: وقت استجابة الطلب الذي أعاد العنوان داخل التطبيق.
- آخر إثراء: وقت جلب تفاصيل المضيف، مستقل عن وقت اكتشافه.
- آخر رصد Shodan: الوقت الذي ذكره المصدر للخدمة أو المضيف، إن توفر.
- الوقت القديم غير المعروف: لا يوجد دليل لاستعادته؛ لا يُستبدل بوقت الترحيل.

التخزين بـUTC والعرض في المستودع بتوقيت `Asia/Aden`. مدخلا فترة البحث
بتوقيت عدن: البداية شاملة والنهاية غير شاملة. منحنى الأيام يعد العناوين
المشاهدة يوميًا، ولا يصنف المستورد القديم كاكتشاف جديد.

لا تُحسب قراءة الكاش أو إعادة رسالة العامل اكتشافًا جديدًا. المفتاح المركب
هو `(المهمة، الطلب، العنوان)`. يبقى الاستعلام الأصلي واستعلام الفرع محفوظين
دون نسب كل قيم facets إلى كل عنوان. تفاصيل المضيف قد تشمل خدمات أخرى؛
لا تُنسب هذه الخدمات تلقائيًا إلى استعلام الاكتشاف.

كل تحديث يحتفظ بالمصدر ووقت الجلب والرصد. القيم الغائبة لا تمسح قيمة موثقة،
واللقطات القديمة لا تعيد وقت آخر إثراء إلى الماضي. تبقى اللقطات المتعارضة؛
العرض المختصر يختار أحدث وقت رصد متاح، ثم وقت الجلب، ثم API عند التعادل.
البورت ذو البروتوكول المجهول لا يضاعف عدّ خدمة أصبح بروتوكولها معروفًا.
الخدمات المسجلة ليست فحصًا حيًا لتوفر المنافذ.

## الإثراء مهمة كاملة

حدد عناوين ثم اختر **إنشاء مهمة إثراء**، أو استخدم الزر دون تحديد لإثراء
نتائج الفلاتر. يستخدم النموذج إعدادات النقل والمهلة والفواصل والميزانية
وإعادة المحاولة وUser-Agent واتصال المهمة. يمكن تحديد موعد وأولوية، واختيار
حساب Shodan من بطاقة المهمة بعد إنشائها.

تظهر المهمة بنوع **إثراء** مع فلتر للنوع. تستخدم نفس الطابور والعامل،
وVPN والتبديل والتشخيص، والإيقاف والاستكمال والإلغاء والنسخ، وسجل الطلبات
والتقارير والتصدير ونقاط الحفظ. زر **إعدادات التشغيل** يعدل الأولوية والموعد
والميزانية والفواصل والتعافي بعد إيقاف المهمة وإغلاق متصفحها.
التقدم هو العناوين المعالجة / إجمالي القائمة، مع فصل النجاح والجزئي وغير
الموجود والمتعثر. وصول المعالجة إلى 100% لا يعني توفر كل التفاصيل.

- **HTML:** قراءة صفحة تفاصيل IP والتحقق من هوية العنوان وبنية البيانات،
  دون مفتاح API.
- **API:** قراءة `/shodan/host/{ip}` مع الخدمات. يطبق خيار التعافي إلى HTML
  عند فشل المصادقة أو الصلاحيات إذا كان مفعّلًا.
- **تلقائي:** API عند توفر مفتاح، وإلا HTML. يجرب البديل عند رفض المصدر
  أو نقص البيانات الأساسية، دون حلقة تبديل بين المصدرين.

تحفظ 429 ومواعيد `Retry-After` في نقطة الاستكمال، وتبقى فعالة بعد إعادة
التشغيل وتبديل المصدر أو VPN. يستخدم فشل الشبكة تعافي العامل الحالي.
قد تتوقف المهمة للمفتاح أو الدخول أو التحقق أو خطأ بنية الصفحة، مع حفظ
نتائجها الجزئية.

المتصفح التفاعلي يستخدم الاتصال المعزول وحساب Shodan الحاليين، والتحكم عن
بعد وتسجيل الدخول وفحص الصفحة والاستكمال الصريح. يحتاج متطلبات VPN
وChromium/Patchright الحالية. يفتح العنوان المعلق من قائمة المهمة، ويتحقق
من مطابقته؛ لا تُقبل وجهات عشوائية من العميل. نجاح النفق أو فتح المتصفح لا
يثبت قبول المصدر. راجع [دليل المتصفح](BROWSER_SESSION_AR.md).

## الإثراء التلقائي والمفتاح

من **إعدادات الإثراء** اختر المصدر الافتراضي وفعّل أو عطّل إنشاء المهام
التلقائية. التعطيل لا يلغي مهامًا موجودة. المصدر الافتراضي يخص المهام
الجديدة؛ تُغيّر المهمة الحالية من نافذة الاستكمال.

تتجمع العناوين القديمة والجديدة التي لم تُثرَ بحسب أقدم مهمة مصدرية موثقة؛
يفصل تاريخ إنشاء المهمة ومعرفها حالات التعادل. ترث المهمة التلقائية إعدادات
المصدر واتصاله وحسابه، مع مصدر إثراء افتراضي `auto` وأولوية منخفضة.
تتوسع قائمتها ما دامت في الطابور ولم تبدأ؛ بعد البداية تثبت القائمة وتدخل
الأهداف اللاحقة مهمة أخرى. تمنع الحجوزات العمل التلقائي المكرر حتى بعد
إلغاء مهمة الإثراء. استخدم مهمة يدوية للتحديث أو إعادة المحاولة؛ لا يوجد
تحديث دوري في هذا الإصدار.

مفتاح API اختياري ومحفوظ مشفرًا بآلية حسابات Shodan، مع الحاجة إلى
`python3-cryptography` للحفظ فقط. المفتاح المشفر في جدول مستقل، ومفتاح فك
التشفير في `shodan-accounts.key` بملكية الخدمة وصلاحية 0600؛ احتفظ به مع
نسخة قاعدة البيانات الاحتياطية. لا يظهر المفتاح في API أو السجلات أو
التقارير أو نقاط الحفظ، ويمر إلى العامل عبر stdin. مفتاح نموذج إنشاء
المهمة أو استكمالها مؤقت؛ الدائم يُدخل من إعدادات المستودع.

## واجهات التكامل والاستعادة

- `GET /api/targets` مع الفلاتر و`offset` و`limit`؛ الافتراضي 100 والأقصى 1000.
- `GET /api/targets/stats` و`GET /api/targets/download?format=txt|csv|json`.
- `GET /api/targets/{id}` مع صفحات سجل الاكتشاف واللقطات ومهام الإثراء.
- `GET/POST /api/enrichment/settings`؛ الرد يعرض وجود المفتاح فقط.
- `POST /api/jobs` مع `kind: enrichment` و`target_ids` أو `filters` وإعدادات
  المهام المشتركة. غياب `kind` يعني `extraction` للتوافق.
- إجراء `configure` عبر `/api/jobs/{id}/actions` لتعديل إعدادات التشغيل،
  بالإضافة لإجراءات pause/resume/cancel/duplicate الحالية.

تحمل نقاط حفظ الإثراء `kind: enrichment` وقائمة الأهداف وحالاتها ولقطاتها
وموعد الانتظار. الاستيراد يتحقق محليًا، ويعيد ربط المعرفات والمسارات ويترك
المهمة متوقفة للمراجعة. نقاط حفظ الاستخراج القديمة مدعومة. راجع الاتصال
والحساب بعد نقل المهمة لخدمة أخرى. حد نقطة الحفظ 32 MiB، وهو حد التطبيق
الحالي لنقاط الاستكمال.

تحفظ لقطة الإثراء قبل إرسالها إلى المدير؛ تعيد الاستعادة الرسالة بنفس
معرف الطلب دون تكرارها. تفاصيل API المستقبلة أثناء الاستخراج تحفظ في
sidecar خاص بالحقول المسموحة لاستردادها عند انقطاع IPC.

## التحقق وحدوده

أداة التحقق التالية تأخذ SQLite backup من المصدر للقراءة فقط، وتنسخ ملفات
النتائج ونقاط الحفظ إلى مجلد مؤقت. تمنع sockets أثناء الترحيل ولا تشغل
الطابور ولا تنسخ المفاتيح أو ملفات المتصفح:

```bash
python3 tools/verify_target_migration.py --source /var/lib/shodan-studio \
  --output /tmp/target-migration.json
```

النتيجة في `target-repository-evidence/migration.json`: حفظ 1,463 عنوانًا
فريدًا من 12 مهمة و2,107 ارتباطات مهمة/عنوان، مع سلامة SQLite وحفظ عقود
المهام. أُنشئت 9 مهام إثراء في النسخة المؤقتة وحُجزت العناوين دون تكرار.
بقيت الأوقات القديمة غير الموثقة مجهولة صراحة.

يستخدم اختبار المتصفح قاعدة مؤقتة و120 عنوانًا اصطناعيًا:

```bash
python3 tests/serve_targets_fixture.py --port 8813
# من طرفية أخرى، مع أدوات المتصفح المثبتة:
NODE_PATH=/usr/lib/node_modules STUDIO_TEST_CHROMIUM=/usr/bin/chromium \
  node tests/browser_targets.cjs http://127.0.0.1:8813
```

الأدلة محلية وعلى نسخة بيانات معزولة؛ لم يُنشر التغيير إلى الخدمة الأصلية
ولم تُجرَ طلبات إثراء حية بعناوينها. محاولة المثال العام من شبكة التطوير
أعادت `NETWORK_UNREACHABLE`؛ نجاح محلل HTML والمتصفح هنا يعتمد على fixtures
معزولة ولا يثبت قبول المصدر من اتصال الخدمة. لم يُجر فحص قارئ شاشة يدويًا.

عند النشر لاحقًا، حدّث التطبيق ومساعد VPN وأعد تشغيلهما على نسخة الكود
نفسها؛ يحتاج العامل المعزول والمتصفح إلى دعم صفحات المضيف الجديد معًا.
