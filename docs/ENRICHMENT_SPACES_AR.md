# مساحتا الاستخراج والإثراء — Issue #35

افتح **`/extraction`** لمهام الاستخراج و**`/enrichment`** لمهام الإثراء.
لكل مساحة طابور وأولوية وعامل تنفيذ مستقل، ويمكن تشغيل عامل من كل نوع معًا.
انتظار التحقق أو الحساب أو VPN في إحدى المساحتين لا يحجز الأخرى.
تبقى قائمة الأهداف وسجل اكتشافاتها مشتركة، وتعمل إجراءات المهمة ونقاط حفظها
وسجلاتها وتصديرها بحسب نوعها دون تغيير معرّفها أو فقد بيانات المهام القديمة.

في إدارة VPN والتشخيص اختر **مساحة الاتصال** قبل تعديل الاتصال أو فحصه.
التحكم باتصال مهمة أو متصفحها من تفاصيلها يُوجّه تلقائيًا إلى المساحة الصحيحة.
تعديل بيانات حساب Shodan المشترك أو حذفه يتطلب توقف العمل وإغلاق المتصفحين.

| المورد | الاستخراج | الإثراء |
|---|---|---|
| الخدمة المساعدة | `shodan-studio-vpn` | `shodan-studio-enrichment-vpn` |
| namespace | `ssvpn-worker` | `ssvpn-enrichment` |
| الواجهة | `ssvpn0` | `ssenrich0` |
| إعدادات VPN | `/etc/shodan-studio/vpn` | `/etc/shodan-studio/vpn-enrichment` |
| ملفات المتصفح | `/var/lib/shodan-studio-browser` | `/var/lib/shodan-studio-enrichment-browser` |
| API الخاص بالمساحة | `/api/jobs` و`/api/vpn` | `/api/enrichment/jobs` و`/api/enrichment/vpn` |

`/api/jobs` يبقى متوافقًا ويعرض النوعين وحالة المساحتين. مسار قائمة الإثراء
يُرجع مهام الإثراء وإحصاءاتها فقط. المسارات كلها تستخدم المصادقة وCSRF الحاليين.
تُعالج ملفات الحفظ القديمة بلا تغيير، والنوع الغائب يعني استخراجًا.

ينشئ Premium للإثراء هوية جهاز مستقلة ثابتة عند ربط الاشتراك الموجود محليًا؛
تُشارك صلاحية الاشتراك وقائمة المواقع، ويُولّد مفتاح نفق مستقل عند الاتصال.
تستهلك الاتصالات المتزامنة خانة لكل جهاز، وتبقى حدود البوابة ومهلها مطبقة.
لا تعني قائمة المواقع أن النفق متحقق؛ عند غياب خانة أو صلاحية أو اتصال تنتظر
المهمة المعالجة. للملفات المستوردة، أضف ملفًا بمفتاح مستقل في مساحة الإثراء.
يمنع القفل بين الخدمتين استخدام مفتاح peer واحد بالتزامن. تبقى شبكة الإدارة
ومسارات الخادم وواجهة Amnezia الأصلية خارج إدارة هاتين المساحتين.

بعد تحديث نسخة التطبيق، ثبّت الوحدتين المتطابقتين مع الكود:

```bash
bash tools/install_vpn_helper.sh --no-start
# عند تثبيت المتصفح للمرة الأولى:
bash tools/install_browser.sh
systemctl enable --now shodan-studio-vpn shodan-studio-enrichment-vpn
systemctl restart shodan-studio
```

خذ نسخة متسقة من البيانات وملفات المتصفح وإعدادات الخدمتين قبل التحديث.
التثبيت ينشئ مجلدات الخدمة الجديدة ولا يستورد ملفات أنفاق الاستخراج إليها.
عند نقل جلسات إثراء من الإصدار السابق، أغلق المتصفح أولًا ثم انقل نسخة خاصة من
ملف حسابه إلى جذر متصفح الإثراء مع إبقاء الملكية والصلاحيات؛ قد يطلب Shodan
تحققًا جديدًا لأن اتصال الإثراء مستقل. لا تُعد البيانات المخزنة في المتصفح
دليلًا على أن Shodan وافق على عنوان الخروج الجديد.

قارئ المضيف يدعم حقول الجدول والحقول المتجاورة في تخطيط General Information
وOpen Ports، وعناوين الخدمات المركبة، حتى دون ملفات CSS. يرفض عنوان IP آخر،
وصفحات الدخول والتحقق وHTTP غير الناجح؛ تبقى المعالجة جزئية إذا غابت معلومات.
تُطلق اكتشافات HTML الإثراء أثناء استمرار الاستخراج. تُحفظ تفاصيل نتائج API
المستلمة أولًا لإعادة استخدامها بدل إرسال طلب إثراء مكرر لها.

أدلة التحقق تحت `enrichment-spaces-evidence/`. اختبارات التوازي تستخدم عمليتي
عامل حقيقيتين وبيانات محلية، واختبارات الواجهة تستخدم حالة مصطنعة وتمنع
الاتصالات الخارجية. نجاحها لا يثبت السماح الحي من Shodan أو نجاح نفق Premium.
يُسجل التثبيت والتحقق الحي وحدوده في ملف دليل مستقل عند إجرائهما.
